### FAQ 발행 알림 응답 지연 수정

발행·수정 뒤 FAQ 역참조를 구하려고 웹훅 응답 전에 CMS 원장을 새로 조회했다. 실측 공개 API 호출은 각각 약 1.9·2.1·2.7초였고, 분류/모델 조회 뒤 글 조회를 하므로 서명 검증까지 합치면 5초 전달 제한을 넘겼다.

FAQ 글 이벤트는 원장 재조회 없이 `faq:all`과 FAQ 동적 경로를 무효화하도록 변경했다. 관련 답변·예약 링크 갱신 범위를 보존하면서 응답 지연을 없앤다. 트레이드오프는 개별 관련 글 대신 FAQ 전체가 다음 방문 때 다시 계산되는 것이다. 다른 유형의 캐시는 그대로 유지한다.

지연된 CMS 모킹으로 기존 라우트의 timeout을 재현한 후 수정했다. 운영 재검증에서 FAQ 수정 알림이 2.5초·1회 시도로 성공하고 공개 상세에 반영됐다. 작성자 아카이브의 기존 422 기록은 위 제약과 같으며 글 발행·수정 연동과 별개다.

추가 원문·사본 매핑·검증 결과는 같은 데이터 디렉터리의 `extra-*`, `faq-before.json`, `reviews-before.json`에 저장한다.
