# FAQ 캐시와 갱신 범위

## 유지해야 하는 동작

FAQ는 CMS가 정한 2단 분류를 사용한다. 분류 이름·개수·소속은 가변적이지만 라우트 깊이는 `/faq/{section}/{topic}/{slug}`다. 글 수정·발행·발행 취소·삭제·주소 이동 뒤 관련 질문과 본문 예약 링크도 최신 공개 상태를 따라야 한다. 갱신 범위를 줄이기 위해 누락 가능성을 받아들이지 않는다.

## 공용 원장 하나를 갱신한다

`faq-api.ts`의 공용 원장은 글과 분류를 함께 캐시한다. FAQ 목록·분류·상세는 모두 이 원장을 읽는다. 상세별 데이터 사본을 영속 캐시하지 않고, 최신 원장에서 요청 글과 관련 질문을 선택한다.

이 구조에서는 명시적인 ID 관계·예약 키·본문 링크뿐 아니라 같은 질환의 자동 추천도 별도 역참조 목록 없이 반영된다. 아직 없는 글을 방문한 뒤 발행하거나, 참조 대상이 삭제되거나, 이전 slug로 참조해도 이전 상세 사본이 남지 않는다. CMS 조회 실패·커서 누락/반복·페이지 안전 상한 도달은 오류로 처리하며, 일부 응답을 정상 원장으로 캐시하지 않는다.

공용 캐시의 전체 FAQ 조회·변환은 유지한다. 단건 조회로 바꾼 것은 아니다. 전체 원장을 읽는 비싼 작업을 상세 페이지마다 반복하지 않는 것이 이번 변경의 범위다. 동시에 들어온 첫 요청들을 전역에서 하나로 합치는 기능은 추가하지 않았다.

**전제:** FAQ 라우트의 `dynamic = 'force-dynamic'`을 유지한다. 정적 HTML 캐시나 상세별 영속 캐시를 다시 도입하면 관련 글 의존성을 별도로 설계하고 이 문서와 통합 테스트를 함께 바꿔야 한다.

## 웹훅 처리

| 입력 | 데이터 캐시 | 경로 |
|---|---|---|
| FAQ 글 이벤트, 상세 주소 포함 | `faq:archive` 즉시 만료 | FAQ 홈·RSS·사이트맵, 전달된 상세, 각 상세의 두 단계 부모 목록 |
| FAQ 글 이벤트, 상세 주소 누락 | 같은 공용 원장 만료 | FAQ 고정 경로와 모든 FAQ 동적 경로 |
| `modelKey: faq`, 경로 없음 | 같은 공용 원장 만료 | FAQ 전체 경로로 보완, 로그에 `faqPathScope: fallback-all` 기록 |
| 분류·테마 변경 | 기존 컬렉션 전체 태그 유지 | 칼럼·후기·FAQ의 기존 전체 경로 |
| 모델과 관계없는 경로 | 변경 없음 | 422로 실패를 드러내 재전송·설정 수정을 가능하게 함 |

CMS가 함께 보내는 이전·현재 상세 주소 모두에서 부모 목록을 계산한다. 웹훅은 CMS 원장을 조회하지 않으므로 역참조 탐색 때문에 응답 제한 시간을 넘기지 않는다. 분류 변경 알림은 대상 모델과 변경 전후의 완전한 범위를 보장하지 않아 전체 갱신을 유지한다.

FAQ 글 변경 때 칼럼·후기 캐시는 건드리지 않는다. 관련 FAQ는 별도의 상세 캐시가 없어 다음 서버 요청에서 갱신된 원장을 읽는다. 이미 열린 브라우저 화면을 강제로 새로고침하는 기능은 아니다.

## Headnerve와의 차이

2026-10-01 로컬 main `aed3b79` 기준 Headnerve는 웹훅에서 CMS 최신 원장을 조회한 뒤 변경 글과 명시적으로 참조하는 글을 선택한다. 자동 추천의 같은 질환 글은 그 계산에 포함되지 않고, 원장 조회 실패 때 폴백 데이터로 대상 계산을 계속한다. 따라서 참조 갱신 누락과 웹훅 응답 지연을 별도 검증해야 한다. Headnerve 코드는 이번 작업에서 변경하지 않았다.

## 회귀 검증

- `src/features/faq/faq-cache.integration.test.ts`: Next의 실제 캐시와 실제 웹훅 라우트·조회·관계 로직을 사용한다. CMS HTTP와 서명 확인만 fixture로 대체한다. 서로 다른 상세 방문의 공용 원장 재사용, 자동 추천·ID·예약 키 참조, 삭제·발행·slug/분류 이동, 분류 이름 변경, 중복·역순 이벤트, CMS 장애·복구를 검사한다.
- `src/app/api/revalidate/route-signature.test.ts`: 실제 ES256 서명과 본문 변경 방지를 검사한다.
- `src/app/api/revalidate/route.test.ts`, `src/features/cms/revalidation.test.ts`: 경로 누락의 안전한 보완, 이전·현재 분류 경로, 다른 컬렉션과의 경계, 웹훅의 CMS 조회 금지를 검사한다.
- `src/features/faq/faq-api.test.ts`: 원장 조회 실패와 불완전한 페이지 응답을 정상 데이터로 저장하지 않는지 검사한다.
